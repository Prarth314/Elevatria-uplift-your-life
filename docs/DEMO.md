# Synthetic demo script

Run `pnpm install --frozen-lockfile`, `npm run build`, `npm run preview`, then open the printed local URL. Use a new browser profile/origin or export existing work before resetting. No API key or account is needed.

1. Show the central vision board and included sample. Say that starter plans are editable local templates, not AI calls.
2. Create “Prepare a campus workshop,” target three weeks from today, budget two hours/week. Change the target date **then** another field and save; verify the date survives. Add a note and generate a starter plan.
3. Edit a task estimate and prerequisites using checkboxes. Attempt a cycle, read the rejection, cancel, and verify focus returns.
4. Add Monday 18:00–20:00 and a dated commitment. Save preferences, generate a proposal, open Placement details, read total unplaced minutes and the heuristic limitation.
5. Review and accept. Reload; accepted allocations remain. Export JSON and ICS. Explain that stable UIDs do not guarantee remote updates/deletions.
6. Complete a task with Space. Show changed effort-weighted progress and disabled stale Calendar export. Reopen it.
7. Use My week changed → deadline → -7 days. Review retained/changed/new/removed work and unplaced effort before accepting. Undo, then generate another proposal and discard it.
8. Open a second tab on the same local URL, edit a synthetic goal, and observe the first tab's conflict warning. Export the first tab's working copy before reload. Never perform this on private or production account data.
9. Restore the downloaded JSON through its preview; cancel once. Point out that restoring replaces, rather than merges, the board.
10. On a narrow viewport, edit a task and inspect the proposal. Mention that keyboard/focus checks are not a full screen-reader audit.

Engineering discussion: show the independent invariant validator, exhaustive counterexample, worker cleanup tests, SQL migration tests and benchmark report. Describe the shared Web Lock plus raw-value conflict guard and the memory-only fallback when coordination is unavailable, and explain why cloud verification still needs a configured development project and two disposable accounts.
